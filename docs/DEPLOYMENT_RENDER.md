## Configuration sequence

1. Create the dedicated Supabase project. The owner enters its database password locally; never put credentials into chat or GitHub.
2. Run existing database migrations with an administrative connection, then use a separate non-owner, non-superuser, `NOBYPASSRLS` application role for web and worker. Do not run the application as Supabase `postgres` or `service_role`. Preserve forced RLS on every app table. Use a TLS database connection and the dashboard-provided connection details; keep migration credentials out of the running service environment.
3. Create a **private** `evidence` storage bucket. Do not add public read policies. Set server-only `SUPABASE_URL`, legacy `SUPABASE_SERVICE_ROLE_KEY` and `SUPABASE_STORAGE_BUCKET`. The storage adapter uses the legacy service-role JWT as Bearer authorization; a new `sb_secret_…` key is not currently interchangeable. Never expose this key in frontend variables. Application record authorization happens before server-side object access. Direct signed uploads remain outstanding.
4. Configure Supabase Auth using `AUTH_MODE=supabase`, `SUPABASE_PUBLISHABLE_KEY` and a fixed `PACK_ORGANIZATION`. Create the operator accounts locally in the dedicated project's Auth dashboard. An administrator must set each user's **app_metadata** `pack_organization` to that same organization and `pack_role` to `operator` or `supervisor` using Supabase's admin API or a reviewed database administration operation. User-editable metadata never grants access. Sign-in uses email/password; public self-registration is not provided by the app. Disable public signups for this private workspace. The backend verifies tokens with Supabase Auth on each request. Public landing page requires no login; never deploy with local authentication mode. No Entra registration is needed for this mode.
5. Run the authorized laptop worker with the local Ollama model and the same Supabase database, private storage and organization configuration. See [LOCAL_VISION.md](LOCAL_VISION.md). Keep Ollama bound to loopback and the worker disabled in Render. The laptop connects outward to Supabase; it must remain on for inspections. Do not put an Ollama localhost URL on Render expecting it to reach the laptop. No Azure or paid model API is used in this plan. Initially use a targeted attempt so historical research captures are not unintentionally processed.
