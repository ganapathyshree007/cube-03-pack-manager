# Prepare the first real inspection

The local DEMO ONLY records explain the interface. They are fictional, have no reference photographs and must not be used to claim model performance. No automated decision has been seeded.

Before real inspections, archive the three DEMO products in Catalogue. Their existing order/inspection history remains available, but they no longer enter new catalogue snapshots.

For a small capability test, provide:

1. Two or three actual products you are authorized to photograph. For each, record SKU, name, variant (colour/size), distinctive visual details and any barcode printed on the item.
2. A clear reference photograph of each product with identifying text visible. Keep private customer labels and addresses out of the frame. The baseline sends at most six reference photographs in total in its single model call.
3. One order with exact SKUs and quantities, and a unique ID for the physical evaluation unit. Do not reuse the same physical unit under another ID to obtain another model call.
4. One open-box photograph showing all items, separated into a single visible layer, with identifying labels readable. Use genuine camera captures; do not substitute generated product images.

Enter products in Catalogue, create the order in Orders and choose it in Inspection. Confirm that the configured model has been capability-tested with a separate non-held-out unit before starting held-out evaluation. Capability testing itself is one call for that unit.

Without a configured model, Save for review stores pending evidence. A new capture does not reset the unit's inference reservation. If inference fails, retain the pending record and use human review rather than retrying the same unit.

The first capability test verifies connectivity and the workflow. It does not establish accuracy. Follow evaluation/PROTOCOL.md for frozen held-out scenes and two independent prior human labels. Official evidence schema compatibility still needs organizer confirmation.
